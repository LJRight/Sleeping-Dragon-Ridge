# 보스 첫 도전·재도전과 마을 부활 검증

아래는 11월 19일 공유 전장의 검증 기록이다. 11월 20일 도전별 전장 분리·파티·의뢰 보상으로 변경한 내용과 현재 실행 방법은 [보스 파티 검증 기록](BOSS_PARTY_TEST.md)에 있다.

2026-11-19, Unity 6000.3.10f1, macOS Apple Silicon. 전용 게임 서버에 두 계정을 동시에 접속해 관문 이동, 사망, 부활, 재도전, 앱 재실행을 검증했다. 일반 사냥터 사망은 별도 계정과 서버에서 확인했다. [실제 게임 화면 녹화](verification/boss-travel/boss-travel.mp4)

영상에서 00:00은 관문까지 이동해 첫 입장하는 장면, 00:12는 보스 전투, 00:33은 사망 안내, 00:35는 마을 메뉴를 이용한 재도전, 00:44는 앱을 다시 실행한 뒤의 플레이 화면이다. 960×540 무음 영상으로, 실제 촬영 구간 네 개를 원래 속도로 연결했다.

## 플레이 방법

1. 경비대장에게 ‘능선의 위협’을 보고한다. HUD가 남동쪽 능선 관문까지의 거리를 표시한다.
2. 사냥터의 관문에 걸어가 **보스 관문 → 도전**을 누른다. 첫 입장에 성공하면 이 계정에서 재도전이 열린다. 관문 안내를 열거나 취소한 단계에서는 계속 잠겨 있다.
3. 솔로 보스전이나 일반 필드에서 사망하면 안내가 뜨고 2.5초 후 가장 가까운 마을에서 자동 부활한다. 현재 등록한 마을은 야영지 한 곳이다. 마을의 **보스 재도전 → 재도전**으로 새 도전을 시작할 수 있다. 두 명 이상 입장한 보스방에서는 전투가 끝날 때까지 생존 동료를 관전한다. [파티 보스 관전](BOSS_PROTOTYPE.md#파티-보스-관전)
4. 살아서 **전장 나가기**를 누르면 이번에 입장한 곳으로 돌아간다. 관문에서 입장했으면 관문, 마을에서 재도전했으면 마을이다.

마을·사냥터·보스 전장은 한 씬에 있으며 전장은 벽으로 구분된다. 입장 기록은 계정별이고, 전장과 보스 체력은 같은 서버에서 공유한다. 보스 처치 보상과 완료 화면은 후속 기획 항목이다.

## 게임 실행 결과

| 상황 | 입력과 관찰 결과 |
|---|---|
| 첫 도전 잠금 | 첫 방문 전에는 마을에 재도전 버튼이 없었다. 마을 메뉴 진입과 원거리 관문 진입을 별도로 요청하자 서버가 모두 거절했다. |
| 현장 첫 입장 | A가 관문에서 취소해도 DB 버전은 6이었다. 다시 도전을 확인하자 전장에 도착하고 버전이 7, 첫 입장 기록이 참이 됐다. 살아서 나가면 관문으로 돌아왔다. |
| 보스전 사망 | A의 일반 공격으로 보스 체력이 줄었고 보스의 공격으로 A의 체력이 116에서 0이 됐다. ‘쓰러졌습니다’ 안내 후 약 2.51초 만에 야영지에서 116/116으로 부활했다. 경험치 40, 골드 47, 장비, 의뢰와 저장 버전 7을 보존했다. |
| 마을 재도전 | 부활한 A가 마을 버튼으로 같은 보스 전장에 입장했다. 나가기를 누르자 마을로 복귀했다. 마을 밖에서는 버튼이 사라졌고 서버도 재도전 요청을 거절했다. |
| 재접속과 계정 분리 | A의 앱 프로세스를 종료한 뒤 다시 접속해 마을에서 재도전했다. 동시에 접속한 B는 체력 116/116, 저장 버전 6과 잠금 상태를 유지했다. SQLite에 A=해금, B=미해금으로 남았다. |
| 일반 사냥터 사망 | 별도 계정이 게임 UI에서 보상 검을 장착한 뒤 사냥터로 걸어갔다. 일반 몬스터 A1에게 11회 피격돼 104→0이 됐다. 약 2.43초 후 야영지에서 104/104로 부활했다. 8.07초간 체력을 유지한 뒤 새 조이스틱 입력으로 이동했다. 경험치·골드·장비·의뢰를 포함한 사망 전후 저장값이 일치했다. |

부활 시간은 클라이언트에서 처음 관찰한 체력 0과 최대 체력 사이의 시간이다. 서버 설정값은 두 경우 모두 2.5초다. [보스 실측값과 DB 결과](verification/boss-travel/boss-flow.json) · [사냥터 피격·부활 실측값](verification/boss-travel/field-death.json)

## 검증 환경과 범위

- 보스 시나리오는 두 임시 계정에 정상 진행 API로 선행 의뢰를 마친 체크포인트를 준비하고 시작했다. 검증 도구가 가로 화면의 조이스틱과 버튼에 입력을 보냈고, 입장·공격·피격·부활은 게임 서버가 처리했다. 잘못된 위치에서 보내는 요청은 동일한 소유자 RPC로 별도 검사했다. 사냥터 시나리오는 의뢰 수락과 장착부터 게임 UI로 진행했다.
- SQLite·HTTP 테스트 10건이 통과했다. 계정별 해금, 기존 계정의 초기 상태, 같은 발견 요청 재시도, 저장 버전 충돌, 장착 아이템·퀘스트 보존을 포함한다. 검증에는 임시 DB를 사용했다. [백엔드 테스트](../localServer/test_gameplay.py)
- 이번 플레이 검증 플랫폼은 macOS다. Android와 iOS 실기기의 터치 영역·프레임 속도와 여러 마을 사이의 거리 선택은 후속 검증 항목이다.
