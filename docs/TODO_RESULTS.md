## 실제 사냥과 이어하기

A는 기본 퀘스트를 수동으로 수행했다. B는 같은 서버에 별도 계정으로 접속해 비교 기준으로 삼았다. 저장 버전은 서버가 확정한 변경 순서다. 동일한 데이터를 다시 조회하거나 인증해도 버전은 증가하지 않는다. [A·B 계정과 DB 보상 ID 및 전체 비교](verification/todo/gameplay.json)

| A에서 관찰한 시점 | 저장 버전 | 누적 XP | 골드 |
|---|---:|---:|---:|
| 최초 입장 | 0 | 0 | 0 |
| 원정 준비 완료, 첫 장비 착용, 사냥 의뢰 수락 | 5 | 0 | 10 |
| 대장간에 꾸러미 전달 | 6 | 0 | 25 |
| A1 첫 처치. 저장 성공 후 응답 유실 | 7 | 20 | 37 |
| 경비대장에게 사냥 보고 | 8 | 40 | 62 |
| 다음 A1 처치 | 9 | 60 | 74 |
| 앱 강제 종료 및 두 서버 재시작 후 재접속 | 9 | 60 | 74 |
| 같은 시점의 B | 0 | 0 | 0 |

첫 처치의 DB 커밋 뒤에 시험용 프록시가 성공 응답을 끊었다. 게임 서버가 동일한 행동 ID로 재전송했고, 그 처치의 보상 행은 한 건이었다. 다음 개체에는 다른 처치 ID가 기록됐다. 재시작 후 A와 B에서 각각 계정, 목표, 아이템별 보유 ID, 착용 상태, 경험치·골드를 포함한 전체 소유자 스냅샷이 종료 전과 일치했다. 복원 조회 실패 후 재시도, 같은 계정의 중복 게임 접속 거부도 확인했다. [저장·복원 실측](verification/todo/gameplay.json)

최종 서버 빌드에서 새 계정 F로 사냥 도중 앱 재시작도 따로 시험했다. 실제 공격으로 드래곤 체력이 28에서 14가 된 시점에 재접속해 사냥 중 상태와 버전 6을 복원했다. 처치 후 보고 전에 다시 재실행해 보고 대기와 버전 7을 복원했고, 경비대장에게 보고하자 버전 8, 누적 40 XP, 62골드가 됐다. [두 재접속의 실측값](verification/todo/hunt-rejoin.json)

## 인벤토리와 장비

왼쪽에 2D 기사·검·투구·방어구·최종 능력치를, 오른쪽에 장착 중인 장비까지 포함한 전체 보유품과 골드를 표시한다. 같은 이름의 검도 보유 ID로 구분한다. 어느 쪽에서 착용품을 열든 동일한 상세 창에 기본값, 등급·강화 증가분, 2·3부위 세트 효과가 표시된다. 기존 로그인 배경, 장비 아이콘과 등급 프레임을 사용했다. ## 실행과 검증 환경

[서버 실행기](../start-servers.command)가 로그인 백엔드와 macOS 전용 서버를 같은 내부 키로 시작한다. Unity 클라이언트는 `Bootstrap → Login Scene → Prototype` 순서로 입장한다. 서버와 다른 기기에서 실행할 때는 그 기기에서 접근 가능한 서버 주소를 사용한다. [실행 안내](../localServer/README.md)

녹화는 개발 DB와 분리한 SQLite, 별도 클라이언트 프로필 및 루프백 포트에서 진행했다. 서버의 퀘스트·장비 변경은 실제 게임 경로로 처리했다. 최종 전용 서버는 `ServerBuild_2`이며 QA 입력·촬영 코드는 격리된 녹화용 플레이어에만 넣었다. 최종 소스·씬·프리팹 99개의 체크섬을 대조했고, 배포 서버에서 두 계정의 마지막 상태와 입력 처리를 다시 확인했다. 모드 전환 검증 뒤 주 편집기를 원래 로그인 씬으로 돌렸고 디스크의 씬은 저장하지 않았다. [빌드 증거](verification/todo/final-builds.txt) · [계정별 비교](verification/todo/gameplay.json)

iPhone 15 Pro 시뮬레이터(iOS 18.6)의 독립 시험 앱에서 프로젝트의 실제 Keychain 플러그인을 사용했다. 서로 다른 세 프로세스에 걸쳐 최초 자격 저장, 복원·갱신, 갱신한 값 복원이 통과했다. Android는 자격 저장 플러그인의 Java·DEX 컴파일과 시험 APK 서명을 확인했다. 연결된 Android 단말은 없었고 페어링된 iPhone은 오프라인이었다. Android 가상 기기 부팅에는 추가 디스크 공간이 필요했다. 실제 Unity 모바일 앱의 종료·재실행 후 계정 복원, 터치 영역·노치 안전 영역, 프레임률은 남은 검증 항목이다. [기기·SDK별 기록](verification/todo/mobile-guest-checks.txt)

## 다음 검토

- **모바일 우선순위.** 먼저 실제 단말에서 게스트 재입장과 두 화면 하단의 터치 영역을 확인한다. 인벤토리의 수치와 강화 표시가 작은 디스플레이에서도 읽히는지가 첫 판단 기준이다.
- **기존 계정 전환.** 정상 연결 시 로그인 화면 진입 약 1.4초 뒤 게스트 접속을 시작한다. 아이디 계정을 자주 쓸 계획이라면 필드 설정에서 언제든 계정을 전환할 수 있게 할지 검토한다.
- **기사 외형.** 현재는 아이콘과 같은 디자인을 기본 복장의 2D 기사에 겹친다. 제출 화면에서 기사 실루엣을 더 강조하려면 부위별 전용 착용 원화를 제작할지 결정한다.
- **퀘스트 조작.** 다음 목표는 자동 안내하고 수락·이동·전투·보고·물품 소모는 수동으로 유지했다. 대사 자동 넘김을 추가할지 먼저 결정할 수 있다. [단계별 검토](QUEST_STORY_FLOW.md)
