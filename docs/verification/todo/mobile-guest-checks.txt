용흔의 능선 · 게스트 저장 및 오프라인 회귀 검증
2026-11-18 KST · macOS arm64 · Unity 6000.3.10f1 · Xcode 26.6

Android 게스트 자격 저장
- Unity Editor의 PluginImporter에서 GuestStore.java는 Android=True, iOS=False.
- 프로젝트에 포함된 실제 GuestStore.java를 Unity OpenJDK javac와 Android API 34 android.jar로 컴파일했다. 별도 시험 앱에서 이 클래스를 D8으로 변환하고 APK에 담아 서명 검사를 통과했다. 시험 앱 식별자는 dev.neoridge.qa.guestprobe.
- adb에 연결된 단말은 0개였다. 기존 API 34 arm64 AVD를 읽기 전용 모드로 실행했으나 에뮬레이터가 “Not enough disk space to run AVD”로 부팅을 거절했다. Keystore 최초 저장·프로세스 종료·복원 및 실제 Unity Android 플레이는 미검증.

iOS 게스트 자격 저장
- Unity Editor의 PluginImporter에서 GuestCredentialStore.mm은 Android=False, iOS=True. UnityFramework에 Security.framework를 추가하는 iOS 빌드 후처리 코드를 확인했다.
- 프로젝트 플러그인 원본을 iphoneos SDK와 arm64-apple-ios13.0 타깃으로 clang++ 구문 검사했다. 같은 원본을 arm64 iOS Simulator 대상 시험 앱에 링크하고 별도 앱 식별자로 설치했다.
- iPhone 15 Pro / iOS 18.6 시뮬레이터는 부팅·설치에 성공했으나 SpringBoard가 앱 시작을 거부했다(FBSOpenApplicationServiceErrorDomain, SBMainWorkspace). 별도 네이티브 프로세스 시도도 launchd_sim 오류 153으로 시작되지 않았다. 두 시험 앱은 제거하고 시뮬레이터를 종료했다.
- Xcode에서 페어링된 iPhone 15가 unavailable로 표시됐다. 실기기 Unity iOS 플레이는 미검증.

iOS 재검증 · iPhone 15 Pro / iOS 18.6 Simulator
- Xcode 표준 앱 타깃에서 원본 GuestCredentialStore.mm을 빌드·서명했다. 앱 식별자는 dev.neoridge.qa.keychain.restore281. 원본 게임의 자격 및 앱 데이터와 독립된 시험 계정을 사용했다.
- 1차 실행 PID 35003에서 기존 값이 없음을 확인하고 임시 자격 P를 저장한 뒤 같은 프로세스에서 다시 읽었다. read=0, write=0, reread=1, passed=true.
- 앱 종료 후 2차 실행 PID 35027에서 저장된 P를 읽고 발급 자격 R로 교체했다. read=1, write=0, reread=1, passed=true.
- 다시 종료한 뒤 3차 실행 PID 35036에서 R 문자열 전체가 같음을 확인했다. read=1, passed=true.
- 별도 시험 앱에 속한 Keychain 레코드를 삭제한 뒤 재조회 값 0을 확인했다. 시험 앱을 제거하고 시뮬레이터를 종료했다. 위 세 단계는 iOS 네이티브 Keychain 연동 자체의 실행 결과다.

Android 재검증 환경
- adb 목록에는 연결 단말이 없었다. Google이 명시한 Emulator 시작 최소 여유 공간은 5 GB이며, 확인 시점 공유 Data 볼륨 여유는 0.7–1.2 GiB였다. 구성된 AVD의 논리적 사용자 데이터 파티션은 6 GiB. 외부 작업용 볼륨은 마운트되지 않았다.
- 격리 Unity 프로젝트 정리 후 재시도했다. AVD 볼륨 여유가 2,009,481,216 바이트(1.87 GiB)일 때에도 에뮬레이터 34.1.18.0은 “Not enough disk space to run AVD”를 기록하고 앱 설치 전에 종료했다.
- 근거  https://developer.android.com/studio/run/emulator-troubleshooting

Unity 경로
- 게임 연동 스크립트를 Unity Roslyn과 기존 프로젝트 참조로 Editor, standalone, iOS/Android 조건부 컴파일했다. 이 분리 검사는 UI 입력 차단 속성만 대체했다. 실제 Editor도 전체 스크립트를 가져와 컴파일하고 새 브리지 타입을 인식했다.
- 오프라인 회귀의 실제 플레이 수치와 화면은 offline-play.txt / offline-attack.png 참조. 기존 Player Controll Test에서 테스트 시작 시 이미 체력 0이었던 플레이어를 로컬 OnEnable로 복구하고 살아 있는 드래곤 서쪽 3.4m에 위치시켰다. 실제 조이스틱과 공격 버튼 입력 → 1.500 m 이동 → 드래곤 HP 100에서 90. 서버 연결·진행 복원은 비활성 상태였다.
- 검증 후 Play 모드를 종료하고 원래 Login Scene, playModeStartScene 없음, runInBackground=false로 복귀했다. 디스크의 로그인 씬에는 저장하지 않았다.

데스크톱 게스트 저장소 동시성
- 실제 GuestCredentialStore.cs를 macOS 조건으로 Mono 테스트 실행 파일에 연결했다. Unity의 저장 경로만 임시 디렉터리로 지정했다.
- 비어 있는 프로필을 8개 프로세스가 동시에 열었을 때 모두 같은 최초 자격을 읽었다. 세 차례의 독립적인 프로필에서 동일하게 통과했다.
- 갱신된 자격을 기록하고 다른 프로세스가 읽었을 때 복원에 성공했다. 게스트 파일 권한은 0600이었고, 파일 내용을 손상시킨 경우에는 새 게스트를 만들거나 기존 파일을 교체하지 않았다.
