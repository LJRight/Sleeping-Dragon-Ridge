# 보스 관문까지의 퀘스트 자동 진행

2026-11-23 · 메인 의뢰 9개, 서브 의뢰 3개

마을 HUD에서 **자동 진행**을 한 번 누르면 캐릭터가 경비대장과 대장장이를 찾아가 의뢰를 수락·수행·보고한다. 인벤토리를 열어 첫 검을 받은 뒤 대장장이에게서 +1로 강화하고 장착한다. 보급 꾸러미도 대장장이에게 전달한다. 사냥이 필요하면 마을 북문을 지나 해당 공터까지 걷고 기존 자동 전투로 싸운다. 자동 진행 중에도 HUD 버튼으로 끄거나 필드에서 조이스틱을 움직여 수동으로 돌아갈 수 있다. 다시 켜면 서버에 저장된 의뢰 상태에서 이어간다.

## 필드 사냥 보상과 전달 의뢰

화염 영혼 포식자와 멧돼지는 수집 의뢰를 수락한 플레이어가 해당 몬스터를 처치할 때마다 **50% 확률로 의뢰 재료 1개**를 준다. 인벤토리에 2개가 모이면 드롭을 멈춘다. 마을의 의뢰 NPC에게 보고하면 재료 2개를 소모하고 보상을 지급한다. 두 서브 의뢰는 수동 보스 입장의 필수 조건에서 제외된다.

처치한 플레이어의 화면 오른쪽에는 실제 지급된 골드·장비·재료의 아이콘, 이름, 수량이 최대 세 줄로 표시된다. 추가 획득분은 차례로 표시하며, 지급 결과는 인벤토리의 골드 잔액과 아이템 목록에서 확인할 수 있다. 몬스터 머리 위에는 방어력을 적용한 최종 피해량이 떠오른다. 남은 체력이 5일 때 최종 피해가 80이면 화면에 80이 뜨고 몬스터의 체력은 0이 된다. 획득 알림의 위치·크기는 [LootFeed 프리팹](../NetmarbleNeo/Assets/Resources/UI/HUD/LootFeed.prefab), 숫자의 글자·시작 위치·지속 시간은 [DamageNumbers 프리팹](../NetmarbleNeo/Assets/Resources/UI/Combat/DamageNumbers.prefab)에서 조절한다.

Unity 6000.3.10f1의 게임 서버와 클라이언트를 별도 플레이 모드에서 실행했다. 임시 계정을 3레벨로 맞추고 서버에서 캐릭터를 배치한 뒤, 클라이언트가 대장장이에게 의뢰를 수락했다. 화염 영혼 포식자의 체력이 46 → 39 → 0으로 줄 때 화면에 7과 39가 떴다. 첫 숫자는 캔버스에서 74.6만큼 올라가며 투명도가 0.003까지 내려간 뒤 사라졌다. 인벤토리와 알림에 같은 심장석 아이콘이 표시됐고, 심장석 2개를 납품하자 골드는 40 → 65, 강화석은 1 → 2가 됐다. 새 클라이언트로 재접속해 목록을 다시 조회했을 때 보유량이 같았고 이전 알림도 뜨지 않았다. [필드 화면](verification/field-loot/field.jpg) · [인벤토리 화면](verification/field-loot/inventory.jpg) · [측정값](verification/field-loot/play-mode.json)

임시 DB 서버 테스트 23개가 통과했다. 두 의뢰 모두 수락 전·완료 후·다른 몬스터·다른 계정의 드롭 제외, 50% 판정 경계, 수집 상한, 납품 소모와 중복 처치 요청을 검증했다. [서버 테스트](../localServer/test_gameplay.py)

단독 전투 씬에서도 앞뒤에 몬스터를 배치해 확인했다. 전방 일반 공격은 앞의 몬스터에만 10을 표시했다. 이어서 회전 베기를 사용하자 앞에는 10, 뒤의 체력 3인 몬스터에는 3이 표시됐다. 숫자가 사라진 뒤 같은 UI 오브젝트가 재사용됐다. [회전 베기 화면](verification/field-loot/local-spin.jpg) · [단독 전투 측정값](verification/field-loot/local-hit.json)

## 대장간에서 강화하기

마을에서 대장장이에게 말을 걸고 **장비 강화**를 선택한다. 목록에서 장비를 고르면 보유량·소모량과 결과별 확률이 표시된다. **강화 시도**를 누르면 서버가 현재 대장장이로부터 4m 이내인지 확인하고 비용과 결과를 함께 저장한다. 일반 인벤토리에서는 장비의 현재 단계와 능력치를 확인하거나 장착할 수 있다.

‘원정 준비’에서 받은 10골드와 ‘첫 담금질’ 수락 때 받은 강화석 1개면 첫 검을 100% 확률로 +1로 올릴 수 있다. 의뢰는 강화 성공 즉시 완료된다. 자동 진행은 이때만 지급 검을 골라 강화한다. 그 후의 강화는 플레이어가 대장간에서 장비를 골라 직접 시도한다. [단계별 비용과 성공 확률](../localServer/inventory.py)

새 게스트의 실제 서버·클라이언트 플레이에서 5.51초에 ‘첫 담금질’을 수락하고 7.22초에 +1 강화가 성공했다. 이 계정은 보급품도 전달해 25골드를 가지고 있었고, 강화 후 15골드와 강화석 0개가 남았다. 9.01초에 같은 검을 장착한 뒤 첫 사냥 의뢰를 수행했다. 서버에 기록된 이 검의 자동 강화는 한 번이었다. [첫 담금질 측정 기록](verification/first-temper/tutorial.json)

별도 새 게스트로 자동 확인창의 중지·취소와 수동 확인창의 취소를 각각 눌러 +0 검과 25골드·강화석 1개가 유지되는 것을 확인했다. 대장장이에게서 6.5m 떨어져 요청하면 서버가 거절했고, 다시 접근해 1.8m에서 수동으로 확정하자 +1 강화와 의뢰 완료가 한 번 저장됐다. 일반 인벤토리의 장비 상세에는 강화 버튼이 없었다. [수동 플레이 측정값](verification/first-temper/manual.json) · [대장장이 대화](verification/first-temper/smith-dialogue.png) · [장비 선택](verification/first-temper/forge-list.png) · [비용과 확률](verification/first-temper/forge-confirm.png)

로그인 서버의 회귀 테스트 21개가 통과했다. 게임 서버의 별도 로직 테스트 7개에서는 강화 요청이 대기하는 동안의 이동·사망과 HTTP 응답 유실을 재현했다. 수동 플레이 검증에는 실제 Unity 클라이언트·서버를, 대기열 경계 조건에는 모의 캐릭터와 HTTP 응답을 사용했다. [서버 회귀 테스트](../localServer/test_gameplay.py) · [대기열 검증 기록](verification/first-temper/bridge-checks.json)

새 의뢰를 포함한 전 구간 측정 중에는 맥북 덮개가 닫혀 클라이언트 연결이 끊겼다. 마지막 연결 표본은 3레벨, 1분 41초였으므로 이 실행의 관문 도착 시간은 측정하지 못했다. 아래 18분 52초는 첫 담금질을 추가하기 전의 완주 기록이다.

이전 버전에서 이미 장착·사냥 의뢰를 시작한 계정은 기존 진행을 이어간다. 지급 검 식별자가 없던 옛 저장에서는 조건에 맞는 일반 균형의 검 중 가장 먼저 생성된 검을 연결한다. 신규 계정에서는 실제로 지급한 장비 한 자루의 식별자를 사용한다. [저장 호환과 서버 테스트](../localServer/README.md)

## 의뢰 사이의 레벨업

의뢰 지정 몬스터 13마리는 1,090 XP를 주고, ‘능선의 위협’ 보고 보상이 20 XP다. 모두 합해도 1,110 XP이므로 20레벨 기준인 2,040 XP까지 930 XP를 별도 사냥으로 벌어야 한다. HUD가 **다음 의뢰 준비 · Lv.○까지 사냥**으로 바뀌면 현재 공터에서 사냥을 계속한다. 보고하러 돌아갈 때는 곧 받을 보고 경험치까지 고려한다.

## 이동·보상·수동 전환

- 이동은 서버의 플레이어 충돌체로 처리한다. 마을과 사냥터 사이에서는 기존 출입구로 이동하고 서버가 지역 전환을 검증한다. 일반 공격의 사거리·콤보·피해·처치 보상은 기존 전투와 같은 규칙을 사용한다.
- 의뢰 진행은 계정의 최신 서버 응답을 기준으로 한다. 수락·보고·전달은 NPC 근처에서 기존 요청을 보내고, 보상은 서버가 지급한다. 사망하면 기존 마을 부활을 기다렸다가 남은 의뢰를 계속한다.
- 새 계정으로 처음부터 자동 진행하면 수집 의뢰 두 개를 포함한 **11개 의뢰**를 마치고, 20레벨에 보스 의뢰를 수락한 뒤 필드 관문에서 멈춘다. 이후 보스 입장 버튼은 플레이어가 누른다. 이미 보스 의뢰를 수락한 계정은 관문으로 바로 돌아간다.

## 첫 담금질 추가 전 플레이 실측

**18분 52초**가 걸렸다. 2026-11-22 macOS에서 Unity 6000.3.10f1 게임 서버와 클라이언트를 독립 실행하고 빈 로그인 DB로 게스트 한 명을 생성했다. 마을에서 자동 진행 버튼에 포인터 클릭을 한 번 보낸 순간부터, 자동 진행이 꺼지고 관문 버튼이 실제 포인터 입력을 받을 수 있는 순간까지 측정했다. 배속은 1배였다. 로그인 이전 시간과 보스전은 측정 범위 밖이다. [플레이 측정값](verification/auto-quest/playthrough.json)

서버 처치 기록은 영혼 포식자 2마리, 화염 3마리, 맹독 6마리, 빙결 6마리, 일반 멧돼지 5마리와 황금 멧돼지 2마리였다. 총 24마리 중 13마리는 의뢰 목표, 11마리는 다음 수락 레벨에 필요한 추가 사냥이었다. 멧돼지 첫 처치 후 한 번 사망했고, 마을 부활 뒤 목표 1/3을 유지한 채 자동으로 같은 사냥터로 복귀했다. 그 왕복과 각 의뢰의 마을 보고 시간까지 포함한 단일 플레이 기록이다.

기획상의 첫 완료 목표는 10~15분이다. 이번 플레이는 보스 도전 전까지 이미 목표 상한을 3분 52초 넘겼다. 20레벨 달성 후 마지막 사냥 의뢰를 보고하고 관문까지 다시 걷는 데 4분 20초가 걸렸다. [기획 분량](PROJECT_PLAN.md)

종료 시 선행 의뢰 8개가 완료됐고 ‘능선의 주인’은 진행 중(0/1)이었다. 측정을 끝낸 프레임에서 관문까지 2.74m였고, 서버에 생성된 보스 도전은 0건이었다. 이 프레임에는 자동 진행 버튼의 이전 이동 문구가 남았다. 이후 표본에서는 관문까지 1.12m였고 ‘보스 도전 준비 완료’가 표시됐다. [측정 종료 프레임](verification/auto-quest/gate.png)

## 첫 담금질 추가 전 조작 전환과 계정 검증

다른 신규 게스트로 첫 사냥터를 걷는 동안 자동 진행을 껐다. 이동이 멎은 뒤 2초간 위치 변화는 0m였고 전투와 의뢰 수치도 멈췄다. 다시 켜고 조이스틱을 끌자 캐릭터가 수동 입력으로 1.05m 움직였고, 손을 떼도 자동 진행은 꺼져 있었다. 다시 버튼을 누르자 같은 사냥 의뢰가 첫 처치로 0/1에서 1/1이 됐다. 배치 에디터에서는 조이스틱 입력 전에 창 포커스 복귀 이벤트를 전달했다. [조작 단계별 관찰값](verification/auto-quest/manual-input.json)

본 실측 계정으로 재접속하자 마을에서 20레벨·선행 의뢰 8개 완료·보스 의뢰 진행 중이 복원됐다. 자동 진행은 꺼진 상태였다. 다시 켜고 관문에 도착하자 ‘보스 도전 준비 완료’와 ‘보스 관문’ 버튼이 함께 표시됐다. 보스 입장 기록은 여전히 0건이었다. [재접속 관찰값](verification/auto-quest/reconnect.json) · [관문 화면](verification/auto-quest/ready.png)

서버 회귀 테스트 18개가 통과했다. 원본 Unity 에디터에서도 새 스크립트와 HUD 프리팹이 컴파일·로드됐고, 의뢰 선택을 여섯 가지 계정 상태로 확인했다. 기존 버전에서 보스 자격을 얻은 계정은 보스 의뢰를 이어가며, 이번 버전에서 멧돼지 사냥을 마치고 보급 의뢰를 남겨 둔 계정은 보급 의뢰를 먼저 선택했다. [서버 테스트](../localServer/test_gameplay.py)
